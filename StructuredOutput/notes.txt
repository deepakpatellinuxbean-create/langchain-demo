LANGCHAIN - STRUCTURED OUTPUT
=============================

Simple idea:
  LLM se free text mat lo (unstructured data).
  LLM se seedha structured data lo (jaise JSON / dict / Pydantic object).


1) PROBLEM KYA HAI?
-------------------

Normal LLM output aise aata hai:

  "This phone has an excellent camera, great battery life,
   but it is expensive. Overall, the sentiment is positive."

Problem:
  - Ye plain text hai
  - Code mein seedha use nahi kar sakte
  - Parse karna padta hai (manual / regex / parser)
  - Kabhi format change ho sakta hai


Structured output aise aata hai:

  {
    "summary": "Excellent phone with great camera and battery.",
    "sentiment": "pos",
    "pros": ["Excellent camera", "Long battery life"],
    "cons": ["Expensive"]
  }

Fayda:
  - Ready-made data milta hai
  - Directly print / store / API / DB mein use kar sakte ho
  - Format fixed rehta hai


Real life example:
  Product review do -> LLM se summary, sentiment, pros, cons nikaalo.
  Ye data dashboard, database, ya API response mein seedha ja sakta hai.


2) LANGCHAIN MEIN KAISA KAAM KARTA HAI?
---------------------------------------

Main method:- with_structured_output(schema) 
with_structured_output me jaisa hum schema pass karte hai vaisa output return karta hai LLM

Flow:
  1. Schema banao (output ka shape)
  2. with_structured_output(schema) use karo
  3. invoke() karo
  4. Structured result mil jaayega


Important: har LLM structured output return nahi karta hai srf kuch models hi support karte hai jaise OpenAI GPT, Gemini, Claude ke supported models.

LLM model jo native structured output support nahi karte hai to unke case me hume:
  - output parsers
  - prompt engineering
  - regex / manual JSON parsing
  use karna padta hai structured output ke liye.


3) SCHEMA BANANE KE 3 TAREEKE
-----------------------------

LangChain mein schema mainly 3 ways se banate hain:

  1. TypedDict   -> lightweight
  2. Pydantic    -> strong + validation
  3. JSON Schema -> language independent (sab languages me support karti hai to agar project multiple languages me hai and structed output dono jagah use hoga to in that case go for JSON Schema)


-----------------------------------------
A) TypedDict
-----------------------------------------

Kya hai?
  Python ka simple type hint style schema.
  Sirf shape batata hai: kaunse fields honge, unka type kya hoga.

Example:

  from typing import TypedDict, Annotated, Optional, Literal

  class Review(TypedDict):
      key_themes: Annotated[list[str], "all key themes"]
      summary: Annotated[str, "brief summary"]
      sentiment: Annotated[Literal["pos", "neg"], "sentiment"]
      pros: Annotated[Optional[list[str]], "list of pros"]
      cons: Annotated[Optional[list[str]], "list of cons"]
      name: Annotated[Optional[str], "reviewer name"]

Phir:

  structured_model = model.with_structured_output(Review)
  result = structured_model.invoke(review_text)


Annotated kyu use karte hain?
  Field ke saath description dete hain.
  Description LLM ko better guide karti hai ki field mein kya likhna hai. Annotated is optional we can simply say key_themes: list[str] 


Pros:
  - Bahut simple
  - Fast likhne ke liye best
  - Type hints milte hain

Cons:
  - Runtime validation nahi karta
  - Galat type aaye to automatically error nahi dega

Example of limitation:
  Agar LLM { "summary": 123 } de,
  TypedDict khud error nahi uthayega.

Kab use karein?
  - Quick demos
  - Simple projects
  - Jab sirf shape chahiye, strict validation nahi


-----------------------------------------
B) Pydantic
-----------------------------------------

Kya hai?
  Python library jo schema + validation dono karti hai.
  Production mein sabse preferred option.

Example:

  from pydantic import BaseModel, Field
  from typing import Optional, Literal

  class Review(BaseModel):
      key_themes: list[str] = Field(description="all key themes")
      summary: str = Field(description="brief summary")
      sentiment: Literal["pos", "neg", "neutral"] = Field(
          description="sentiment of review"
      )
      pros: Optional[list[str]] = Field(default=None, description="pros")
      cons: Optional[list[str]] = Field(default=None, description="cons")
      name: Optional[str] = Field(default=None, description="reviewer name")

Phir:

  structured_model = model.with_structured_output(Review)
  result = structured_model.invoke(review_text)


Pydantic ka special power = Runtime Validation

Example 1:
  Expected: age: int
  LLM returns: { "age": "21" }
  Pydantic isko 21 (int) mein convert kar deta hai.

Example 2:
  LLM returns: { "age": "abc" }
  ValidationError aa jaayega.


Pros:
  - Runtime validation
  - Type conversion
  - Better error messages
  - Default values
  - Optional fields
  - Nested models support

Cons:
  - TypedDict se thoda zyada code
  - Mostly Python focused


Kab use karein?
  - Real apps / production
  - Jab data sahi format mein chahiye
  - Jab wrong data pe error chahiye


-----------------------------------------
C) JSON Schema
-----------------------------------------

Kya hai?
  Schema ko pure JSON format mein likhte ho.
  Ye language independent hai (Python, JS, Java, Go, etc.).

Example:

  json_schema = {
    "title": "Review",
    "type": "object",
    "properties": {
      "summary": {"type": "string"},
      "sentiment": {
        "type": "string",
        "enum": ["pos", "neg", "neutral"]
      },
      "pros": {"type": ["array", "null"], "items": {"type": "string"}},
      "cons": {"type": ["array", "null"], "items": {"type": "string"}}
    },
    "required": ["summary", "sentiment"]
  }

Phir:

  structured_model = model.with_structured_output(json_schema)
  result = structured_model.invoke(review_text)


Important point:
  JSON Schema sirf rules define karta hai.
  Khud validation nahi karta.
  Validation ke liye alag library chahiye (jaise Python mein jsonschema).


Pros:
  - Language independent
  - Industry standard
  - APIs mein common

Cons:
  - Thoda verbose (zyada likhna padta hai)
  - Python projects mein Pydantic usually easier lagta hai


Kab use karein?
  - Multi-language systems
  - API contracts
  - Jab schema JSON file se share/reuse karna ho


4) QUICK COMPARISON
-------------------

TypedDict:
  - Simple
  - No runtime validation
  - Best for quick demos

Pydantic:
  - Strong + validated
  - Best for real Python apps

JSON Schema:
  - Language independent
  - Best for APIs / multi-language


Feature                TypedDict     Pydantic      JSON Schema
---------------------------------------------------------------
Easy to write          Best          Good          Verbose
Type hints             Yes           Yes           Yes
Runtime validation     No            Yes           Needs library
Language independent   No            No            Yes
Production ready       Average       Best          Good


5) with_structured_output() KE METHODS
--------------------------------------

LangChain/OpenAI context mein mainly 2 methods: hum with_structured_output me method type bhi bhej sakte hai. OpenAI recommend karta hai function_calling use kia jaaye. 

A) Function Calling  (Recommended)

  structured_model = model.with_structured_output(
      Review,
      method="function_calling"
  )

Kya hota hai?
  Model ko function ka schema diya jata hai,
  aur model uske arguments generate karta hai.

Kyun best hai?
  - Zyada reliable
  - Schema better follow karta hai
  - Hallucination kam
  - Agents/tools ke saath naturally fit hota hai

Kab use karein?
  - AI Agents
  - Tool calling (search, calculator, weather, DB, email, etc.)
  - Production apps


B) JSON Schema / JSON Mode

  structured_model = model.with_structured_output(
      Review,
      method="json_schema"
  )

Kya hota hai?
  Model se bola jata hai: valid JSON do jo schema follow kare.

Kab use karein?
  - Jab sirf structured JSON chahiye
  - Jab koi tool execute nahi karna
  - Simple extraction tasks


Simple rule:
  Agent / Tools  -> Function Calling
  Sirf data nikaalna -> Function Calling ya JSON Schema (dono ok)
  OpenAI models  -> Function Calling usually safer choice


6) PRACTICAL USE CASES
----------------------

Structured output kahan useful hai:

  - Sentiment analysis
  - Review extraction (summary, pros, cons)
  - Invoice parsing
  - Resume parsing
  - Form filling / data extraction
  - Chatbot se fixed format response lena


7) FINAL CHEAT SHEET
--------------------

Q: Structured output kya hai?
A: LLM se fixed format mein data lena.

Q: LangChain mein kaise karte hain?
A: model.with_structured_output(schema)

Q: Schema kaise banayein?
A:
  - TypedDict  -> simple
  - Pydantic   -> best for Python + validation
  - JSON Schema -> best for multi-language / APIs

Q: Method kaunsa choose karein?
A:
  - Function Calling -> recommended (esp. agents/tools)
  - JSON Schema method -> simple structured JSON ke liye


One-line memory:
  Schema define karo -> with_structured_output() lagao -> clean structured data lo.
