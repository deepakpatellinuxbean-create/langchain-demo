================================================================================
DOCUMENT LOADERS — NOTES
================================================================================

Document Loader kya hai?
  Kisi bhi type ke document (txt, pdf, webpage, folder...) ko
  LangChain ke Document format me load karna.

Loader hamesha kya return karta hai?
  list of Document objects

Har Document object me generally 2 cheezein hoti hain:
  1) page_content → actual text content
  2) metadata     → source, page number, URL, encoding, etc.


--------------------------------------------------------------------------------
IS FOLDER ME 5 LOADERS
--------------------------------------------------------------------------------

1) TextLoader       → plain .txt file
2) PyPDFLoader      → PDF file (1 page = 1 Document)
3) DirectoryLoader  → poora folder (multiple files)
4) WebBaseLoader    → webpage / URL
5) CSVLoader        → CSV file (1 row = 1 Document)


================================================================================
1) TEXT LOADER (TextLoader)
   File: text_loader.py
================================================================================

Kya hai?
  Plain .txt files ko load karta hai.
  Simple use: poem, notes, article text file.

Important params:
  file_path → kaunsi file load karni hai
  encoding  → aksar "utf-8" (Windows pe safe)

Return:
  Usually 1 file = 1 Document object
  docs[0].page_content → file ka text
  docs[0].metadata     → source path etc.

Demo flow (text_loader.py):
  TextLoader se poem load → PromptTemplate → ChatOpenAI → summary


================================================================================
2) PDF LOADER (PyPDFLoader)
   File: pyPDF_loader.py
================================================================================

Kya hai?
  PDF file ko load karta hai.
  HAR PAGE ke liye ALAG Document object banata hai.

Example:
  PDF me 20 pages → loader.load() → list me 20 Document objects
  docs[0] = page 1, docs[1] = page 2, ...

Har Document me:
  page_content → us page ka text
  metadata     → source path, page number, etc.

Limitation:
  Sirf TEXT-based / normal PDFs padhta hai.
  Scanned pages, image screenshots, OCR content → sahi nahi padhega.


--------------------------------------------------------------------------------
Kab kaunsa PDF loader? (quick guide)
--------------------------------------------------------------------------------

Use Case                          Recommended Loader
--------------------------------  ----------------------------------------------
Simple, clean text PDF            PyPDFLoader
Tables / columns                  PDFPlumberLoader
Scanned / image PDF               UnstructuredPDFLoader / AmazonTextractPDFLoader
Layout + images bhi chahiye       PyMuPDFLoader
Best structure extraction         UnstructuredPDFLoader

Short explanation:
  PyPDFLoader           → simple text PDFs, light processing
  PDFPlumberLoader      → tables/columns preserve karne me better
  UnstructuredPDFLoader → complex PDFs (images, scanned, headings, structure)
  AmazonTextractPDFLoader → scanned/image PDFs (OCR via AWS Textract)
  PyMuPDFLoader         → text + layout/images, generally fast


================================================================================
3) DIRECTORY LOADER (DirectoryLoader)
   File: directory_loader.py
================================================================================

Kab use karein?
  Jab ek poora FOLDER load karna ho jisme multiple files hon.
  Example: pdf_files_directory me kai PDFs → saari load.

Important params:
  path       → kaunsa folder
  glob       → kaunsi files (pattern dena padta hai usually)
  loader_cls → har file ke liye kaunsa loader
               (PDFs ke liye PyPDFLoader)

Common glob patterns:
  "*.pdf"      → current folder me sirf .pdf
  "**/*.txt"   → saari subfolders me .txt
  "data/*.csv" → sirf data/ folder me .csv
  "**/*"       → har type ki har file (all subfolders)

PyPDFLoader ke saath note:
  Har PDF page = 1 Document
  Example: 3 PDFs, total 15 pages → total 15 Documents


--------------------------------------------------------------------------------
load() vs lazy_load() — IMPORTANT
--------------------------------------------------------------------------------

load():
  - Saari files/pages ek sath memory me list banata hai
  - Return: list of Document objects
  - Zyada files → slow + memory heavy

lazy_load():
  - Generator return karta hai
  - Ek baar me 1 Document yield
  - Memory + time dono bachate hain
  - DirectoryLoader me usually yahi prefer karo
  - Jab agla document load hota hai memory me to previous document memory se remove kr dia jata hai

Important:
  Generator pe indexing (docs[4]) NAHI chalti.
  Indexing chahiye to:
    docs = list(loader.lazy_load()) # (yaad rahe: list() karne se saara data memory me aa jata hai)
  Ya pure lazy style:
    for doc in loader.lazy_load():
        print(doc.page_content)


================================================================================
4) WEB BASE LOADER (WebBaseLoader)
   File: webbase_loader.py
================================================================================

Kya hai?
  Web page (URL) se text content load karta hai.
  Under the hood BeautifulSoup HTML parse karke visible text nikalta hai.

Kab use karein?
  Blogs, news articles, public websites —
  jahan content mainly TEXT-based aur STATIC ho.

Limitations:
  - JavaScript-heavy pages sahi nahi load hoti
    (dynamic content ke liye SeleniumURLLoader better)
  - Sirf static HTML content aata hai
    (page render ke baad JS se aane wala data miss ho sakta hai)

Multiple URLs:
  Ek URL string ya URLs ki list dono pass kar sakte ho.
  Example:
    loader = WebBaseLoader(url)
    loader = WebBaseLoader([url1, url2])

Return:
  list of Document objects
  Usually 1 URL = 1 Document
  docs[0].page_content → extracted text
  docs[0].metadata     → source URL etc.

Demo flow (webbase_loader.py):
  URL load → page text → Prompt + question → ChatOpenAI → answer


================================================================================
5) CSV LOADER (CSVLoader)
   File: csv_loader_5.py
================================================================================

Kya hai?
  CSV file ko load karke LangChain Document objects banata hai.

Important rule:
  HAR ROW = ALAG Document object

Example:
  CSV me 100 data rows → loader.load() → 100 Documents

Har Document me:
  page_content → us row ke columns "key: value" form me (har column nayi line pe)
  metadata     → usually {"source": file_path, "row": row_index}

page_content example (ek row):
  name: Aarav
  city: Delhi
  age: 22
  role: Student

Useful optional params:
  source_column    → metadata["source"] me file path ki jagah kisi column ki value
  metadata_columns → kuch columns page_content me nahi, metadata me daal do
  content_columns  → page_content me sirf selected columns
  encoding         → file encoding (jaise "utf-8")

Kab use karein?
  Tabular data (employees, products, FAQs, records) ko
  RAG / search / LLM ke liye Documents me convert karna ho.

Sample file:
  csv_file.csv


================================================================================
QUICK DECISION GUIDE
================================================================================

Plain .txt file                 → TextLoader
Single text PDF                 → PyPDFLoader
Tables/columns PDF              → PDFPlumberLoader
Scanned/image PDF               → Unstructured / Textract
Poora folder (multiple files)   → DirectoryLoader (+ sahi loader_cls)
Webpage / blog / article URL    → WebBaseLoader
JS-heavy dynamic webpage        → SeleniumURLLoader
CSV / tabular rows              → CSVLoader


================================================================================
COMMON PATTERN (almost sab loaders me)
================================================================================

loader = SomeLoader(...)
docs = loader.load()          # list of Documents

docs[0].page_content          # text
docs[0].metadata              # source / page / url / row etc.

Phir next steps usually:
  Text Splitting → Embeddings → Vector Store → RAG / QA
