Vector Store kya hota hai?

# vector store wo system hai jo data ko embeddings (numerical vectors) ki form me store karta hai
# phir query aane par similar vectors dhoondh ke relevant data return karta hai

# flow simple hai:
# 1. documents / text / images -> embeddings
# 2. embeddings vector store me save
# 3. query aayi -> query ka bhi embedding banao
# 4. similar vectors search karke relevant docs nikaalo


Key features:

1) Storage
# vectors + unka metadata store hota hai
# in-memory (RAM) -> fast, lekin process band hua to data gayab (persist alag se karna padta hai)
# on-disk (SSD/HDD) -> durable, bade data ke liye better
# on-disk ko ROM mat samajhna. ROM read-only memory hai, disk persistent storage hai

2) Similarity Search
# query vector ke sabse similar vectors retrieve karta hai
# common metrics: cosine similarity, Euclidean distance, inner product (dot product)

3) Indexing
# high-dimensional vectors par fast search ke liye index banata hai
# exact nearest neighbor har baar feasible nahi (bahut slow)
# isliye aksar Approximate Nearest Neighbor (ANN) use hota hai
# thoda accuracy trade-off, speed bahut zyada

4) CRUD
# Create -> naye vectors add
# Read -> vectors / similar results nikaalna
# Update -> existing entry update
# Delete -> outdated vectors hataana


Use-cases:
1) Semantic Search  -> keyword nahi, meaning ke hisaab se search
2) RAG              -> LLM ko relevant context dena
3) Recommender      -> similar items / users suggest karna
4) Image/Multimedia -> embeddings se similar media dhoondhna



Vector Store vs Vector Database

# dono related hain, same cheez nahi

Vector Store:
# lightweight library/service
# kaam: embeddings store + similarity search
# traditional DB features aksar nahi: transactions, rich query language, RBAC, replication etc.
# prototyping / small apps ke liye achha
# example: FAISS
# FAISS search deta hai, lekin persistence, scaling, auth, backup alag se handle karna padta hai

Vector Database:
# full database jo vectors store + query ke liye bani hai
# extra features:
#   - horizontal scaling
#   - durability / persistence (replication, backup)
#   - metadata filters
#   - ACID / near-ACID (product pe depend)
#   - auth / security
# production + large datasets ke liye

# simple:
# vector database = vector store + extra DB features (scaling, security, filtering, durability)

# examples: Pinecone, Qdrant, Weaviate, Chroma
# Chroma ko vector DB bhi kaha jata hai, local/dev use bhi common hai
